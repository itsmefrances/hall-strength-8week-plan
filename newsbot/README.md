# UWS Instagram News Bot

Automatically watches [I Love The Upper West Side](https://www.ilovetheupperwestside.com),
and for each new article: writes an original 75–150 word summary and caption with
an LLM, renders a branded 1080×1080 graphic, and publishes it to an Instagram
Business account via the Instagram Graph API — all unattended, on a schedule.

## How it works

```
GitHub Actions (every 10 min)
  └─ python -m newsbot
       1. monitor.py   – RSS feed (autodiscovered; /feed/ for WordPress) or homepage scrape
       2. storage.py   – SQLite dedup: skip anything already processed
       3. extract.py   – title, og:image, publish date, body text (JSON-LD aware)
       4. generate.py  – OpenAI: original summary + caption hook + local hashtags
       5. graphic.py   – Pillow: 1080×1080 branded graphic (headline over featured photo)
       6. hosting.py   – commits PNG to this repo → public raw.githubusercontent.com URL
       7. publish.py   – Graph API: create media container → poll → publish
       8. storage.py   – record post ID/permalink/errors in SQLite + newsbot/state/log.jsonl
```

State (`newsbot/state/`) is committed back to the repo after each run, so the
bot never double-posts even though each Actions run starts from a fresh VM.

**First-run safety:** the first ever run *seeds* the database with everything
currently on the site and posts nothing, so enabling the bot doesn't flood the
account with old stories. Only articles that appear after that get posted, at
most `MAX_POSTS_PER_RUN` (default 2) per run.

## Setup

### 1. Instagram / Meta prerequisites

Automated publishing requires an **Instagram Business account connected to a
Facebook Page** (a personal or Creator account will not work).

1. Convert the Instagram account to Business and link it to a Facebook Page.
2. Create a Meta app at <https://developers.facebook.com> and add the
   **Instagram Graph API** product.
3. Get a **long-lived access token** with `instagram_basic`,
   `instagram_content_publish`, and `pages_read_engagement` permissions
   (a System User token from Meta Business Suite is best — it doesn't expire
   every 60 days).
4. Find the Instagram Business account ID:
   `GET /me/accounts` → page ID → `GET /{page-id}?fields=instagram_business_account`.

Note: the Graph API caps content publishing at 25 posts per 24 hours per account.

### 2. Repository secrets

In **Settings → Secrets and variables → Actions**, add:

| Secret | Value |
|---|---|
| `OPENAI_API_KEY` | OpenAI API key |
| `IG_ACCESS_TOKEN` | long-lived Graph API token |
| `IG_USER_ID` | Instagram Business account ID |

The built-in `GITHUB_TOKEN` handles image hosting and state commits — no extra
secret needed. **The repo must be public** so Instagram can fetch the graphic
from `raw.githubusercontent.com`. (If the repo must stay private, host the PNGs
elsewhere — e.g. S3 — and swap out `hosting.py`.)

### 3. Enable

The workflow (`.github/workflows/newsbot.yml`) runs every 10 minutes once it's
on the default branch. Trigger it manually from the Actions tab (with the
optional **dry run** checkbox) to test.

## Configuration

All optional — see `.env.example` for the full list. Highlights:

| Env var | Default | Meaning |
|---|---|---|
| `MAX_POSTS_PER_RUN` | `2` | rate limit per run; extras post on later runs |
| `REQUIRE_APPROVAL` | `false` | queue posts in `state/pending/` instead of publishing |
| `DRY_RUN` | `false` | build caption + graphic locally, never publish |
| `SEED_ON_FIRST_RUN` | `true` | first run records existing articles without posting |
| `BRAND_NAME` / `ACCENT_COLOR` / `LOGO_PATH` | — | graphic branding |
| `FEED_URL` | autodiscovered | explicit RSS URL override |
| `OPENAI_MODEL` | `gpt-4o-mini` | any OpenAI chat model |

## Running locally

```bash
pip install -r newsbot/requirements.txt
cp newsbot/.env.example newsbot/.env   # fill in, then export the vars
python -m newsbot --dry-run -v         # safe: writes graphics + captions to newsbot/state/
python -m unittest discover -s newsbot/tests -t .
```

Dry run works without any API keys (it falls back to an extractive summary),
which is handy for checking article discovery and the graphic layout.

## Content & compliance notes

- Summaries are **original text** generated by the LLM with explicit
  instructions never to copy sentences; every caption credits
  *I Love The Upper West Side* and points readers to the link in bio.
- Keep the source site's latest article link in the Instagram bio (or use a
  link-in-bio tool) so the CTA is honest.
- Respect the site's Terms of Service. The bot sends a descriptive
  `User-Agent` and makes one homepage/feed request per run plus one request
  per new article.
- Featured images belong to the source site. If you don't have permission to
  reuse them, unset the photo by setting a `LOGO_PATH`-only branded layout —
  the graphic renders fine with no photo (solid background + headline).

## Troubleshooting

- **Nothing posts:** check the Actions log. The first run only seeds; a run
  with no new articles logs "No new articles".
- **`Media container failed processing`:** Instagram couldn't fetch the image
  URL — usually a private repo. Make the repo public or host images elsewhere.
- **Token expired:** long-lived user tokens last ~60 days; use a System User
  token to avoid rotation.
- Every article's outcome (`posted` / `error` + message) is in
  `newsbot/state/newsbot.db` and `newsbot/state/log.jsonl`.
